# BardWiki 사용 가이드

BardWiki는 대화에서 일어난 사건과 오래 기억할 정보를 Markdown 문서로 정리하는 리스바드의 장기 메모리입니다. 문서를 직접 읽고 고칠 수 있으며, 다음 답변에는 현재 대화와 관련된 기억만 골라 전달합니다.

## 빠른 시작

1. BardWiki 상단의 **설정**을 열어 **현재 챗 설정**을 확인합니다. 위키 작업에 쓸 **작업 모델**과 **위키 작성 언어**를 정하세요. 보조 모델을 선택했다면 해당 모델의 연결 설정도 필요합니다.
2. **응답 최근 메시지**와 **분석 최근 메시지**를 확인합니다. 기본값은 각각 12개입니다. 두 값의 차이는 아래 핵심 설정에서 설명합니다.
3. 평소처럼 대화를 진행합니다. 확정된 응답은 자동으로 분석됩니다. **작업 공간**에서 인물·장소 등의 문서를, **이야기**에서 사건 요약을 확인하세요. 확정 시점은 아래 **자동 분석과 추가 분석**에서 설명합니다.
4. 빠진 정보는 **추가 분석**으로 점검하고, 원하는 내용을 직접 고치려면 문서 편집기나 **위키 관리자 명령**을 사용합니다.
5. 이미 쌓인 대화 전체로 위키를 새로 만들고 싶다면 **위키 리부트**를 사용합니다. 리부트 중에는 새 응답을 생성할 수 없으며, 기존 위키는 새 위키가 완성된 뒤에 교체됩니다.

## BardWiki의 컨셉

**최근 대화는 원문으로, 오래된 기억은 위키로 전달합니다.** 매번 전체 채팅과 전체 위키를 모델에 다시 보내는 방식이 아닙니다.

- **채팅 원문**은 실제로 무엇을 주고받았는지 확인하는 근거입니다. 최근 메시지 수를 줄여도 저장된 채팅이 삭제되지는 않습니다.
- **사건 문서**는 확정된 응답에서 실제로 일어난 일을 자세히 기록합니다. **정본 문서**는 다음 장면에서 바로 쓸 현재 상태·관계·지식, 장소와 물건 등 지속 정보를 정리한 다이나믹 로어북입니다. 캐릭터의 전환점과 아크 플롯은 상세 사건을 찾는 지도 역할을 합니다.
- **답변 생성**에서는 캐릭터·세계관 설정, 현재 입력을 포함한 최근 대화, 검색으로 고른 위키 기억을 조합합니다. 위키가 커져도 모든 문서를 한 번에 읽지는 않습니다.
- **위키 작성**은 답변 생성과 별도의 AI 작업입니다. 분석할 원문 수, 작업 모델과 토큰 예산도 따로 조절합니다.

따라서 오래된 정보가 빠졌다면 최근 메시지 수만 늘리기 전에 해당 내용이 위키에 기록되어 있는지, 현재 질문과 관련된 문서로 조회되는지 확인하세요.

실제 장기 역할극에서 전체 채팅 재전송 방식과 비교한 속도·품질·비용 결과는 [장기 채팅 실험 보고서](memory-wiki-long-chat-experiment.md)를 참고하세요.

## 먼저 확인할 핵심 설정

채팅 범위·예산의 전역 기본값은 앱 **설정 → 리스바드 → 채팅 모드**에서, 위키 언어와 문체는 **리스바드 → 공통 설정**에서 바꿉니다. 이 대화만 다르게 쓰려면 **BardWiki → 설정 → 현재 챗 설정**에서 변경하세요. 현재 챗에 별도로 지정한 값이 전역값보다 우선하며, **전역값 사용**을 누르면 이 챗의 개별 설정 전체를 지우고 전역값을 따릅니다. 아래 괄호는 현재 챗 설정에 표시되는 이름입니다.

### 1. 매 답변에 몇 개의 채팅을 보낼까?

**LLM에 전달할 최근 채팅 내역** (**응답 최근 메시지**)는 새 답변을 만드는 모델에 전달할 최근 원문 메시지의 최대 개수입니다. **현재 사용자 요청도 이 개수에 포함**됩니다.

- 단위는 **왕복 턴 수가 아니라 메시지 수**입니다. 사용자 입력 하나와 AI 답변 하나를 합치면 2개입니다.
- 예를 들어 12로 설정하면, 기록이 충분할 때 **현재 사용자 입력 1개 + 그 직전 메시지 11개**를 전달합니다. 12번의 왕복 대화나 12개의 AI 답변을 뜻하지 않습니다.
- 값을 높이면 직전 대화의 말투·세부 묘사·진행 흐름을 더 오래 직접 참조할 수 있지만 입력 토큰과 비용, 응답 시간이 늘어날 수 있습니다.
- 값을 낮추면 원문 입력이 줄고 위키 기억의 비중이 커집니다. 너무 낮으면 아직 위키에 담기지 않은 직전 맥락을 놓칠 수 있습니다. 별도로 검색한 위키 문서는 이 메시지 개수에 포함되지 않습니다.

**과거 사용자 메시지 제외** (**사용자 메시지 제외**)를 켜면 과거 사용자 입력을 제외하고 최근 AI 답변과 현재 사용자 요청을 기준으로 개수를 셉니다. 현재 사용자 요청은 유지됩니다. 과거 입력에만 있는 지시나 설정도 빠질 수 있으므로 주의하세요. 이 옵션은 답변 생성용이며 위키 분석 원문의 사용자 메시지를 제외하는 설정은 아닙니다.

### 2. 위키를 쓸 때는 몇 개의 원문을 읽을까?

**위키 분석 최근 원문** (**분석 최근 메시지**)는 위키 갱신 시 분석 대상 응답까지의 최근 사용자·AI 메시지를 문맥으로 얼마나 참고할지 정합니다. 답변 생성용 개수와는 독립적입니다.

값을 높이면 인과관계와 지칭 대상을 파악할 앞뒤 문맥이 늘지만 분석 입력량도 늘어납니다. 낮추면 분석 부담은 줄어도 짧은 응답이나 대명사의 의미를 놓칠 수 있습니다. 사용자의 요청 자체를 이미 일어난 사건으로 기록하지는 않습니다.

예를 들어 **응답 12개 / 분석 6개**라면, 새 답변에는 최대 12개의 최근 메시지를 보내고 위키 갱신에는 분석 대상까지 최대 6개의 최근 메시지를 참고합니다. 두 값을 더해 18개의 대화를 한 번에 보내는 것이 아닙니다. 이 설정은 **리부트의 1턴·2턴 갱신 단위**와도 다릅니다.

### 3. 위키 작성 언어

**위키 작성 언어**는 사건 분석·요약과 정본 본문을 **한국어 / English** 중 어떤 언어로 쓸지 정합니다. 기본값은 한국어이며 **UI·대화 언어와 독립적**입니다. 한국어로 대화하면서 위키만 영어로 기록할 수도 있습니다.

- **리스바드 → 공통 설정**에서 기본 언어를 정하고, 현재 챗에서 다른 언어를 지정할 수 있습니다. 언어 항목의 **공통 설정 사용**은 다른 챗 설정을 유지하면서 언어만 공통값을 따르게 합니다.
- 이 선택은 사용자 지정 문체나 Wiki Guide에 적힌 언어 지시보다 우선합니다. 기존 문서 제목·위키 링크 대상·고유명사와 필요한 근거 인용은 보존합니다.
- **기존 문서는 자동 번역되지 않습니다.** 설정만 바꾸면 이후 작성·갱신부터 적용됩니다. 대화 전체를 새 언어로 다시 정리하려면 언어를 고른 뒤 **위키 리부트**를 실행하세요. 이는 기존 문서의 일괄 번역이 아니라 채팅 근거로 위키를 새로 만드는 작업입니다.
- **리부트는 시작할 때 선택한 언어를 유지**하며, 중간에 설정을 바꾸거나 작업을 재개해도 그 언어로 계속합니다. 다른 언어로 기록된 기존 사건에는 추가 분석을 덧붙이지 않습니다.

### 4. 위키를 얼마나 읽고, 얼마나 분석할까?

**조회 예산**은 이미 있는 위키를 읽는 양이고, **분석 예산**은 위키를 쓰는 AI 작업의 한도입니다. 최근 메시지 개수와 달리 단위는 토큰입니다.

- **위키 조회 토큰 목표** (**검색 목표 토큰**, 기본 2,000): 일반 조회에서 관련 문서를 고를 때 사용하는 목표입니다. 관련 문서가 적으면 억지로 채우지 않습니다.
- **사건 상세 조회 토큰** (**사건 검색 토큰**, 기본 2,000): 과거·원인·세부·연대기 질문에서 캐릭터 전환점과 아크 플롯을 지도 삼아 상세 사건 문서를 가져오는 별도 예산입니다. 현재 상태 질문만으로는 이 예산을 사용하지 않으며, 일반 조회와 사건 조회의 합계는 절대 상한을 넘지 않습니다.
- **위키 조회 토큰 절대 상한** (**검색 최대 토큰**, 기본 6,000): 상세 조회와 필수 문서를 포함한 위키 조회 한도입니다. 목표보다 작게 설정하면 목표도 이 값으로 제한됩니다. 전체 채팅 입력이나 모델의 출력 길이 한도는 아닙니다.
- **AI 분석 토큰 상한** (**분석 토큰 한도**, 기본 8,192): 사건 분석·리부트·정본 재작성 등 위키 AI 작업의 입력과 출력에 적용하는 예산입니다. 최근 원문을 많이 주더라도 이 한도에 맞추면서 참고 본문이 축소될 수 있습니다. 필수 입력도 담을 수 없으면 실패로 표시됩니다.
- **분석 1회당 자동 정본 대상 한도** (**정본 대상 한도**, 기본 8): 한 번의 자동 분석에서 새로 만들거나 갱신할 정본 문서 수입니다. 등장인물과 변화가 많은 장면에서 너무 작으면 한 번에 반영할 대상이 줄어듭니다. 위키 관리자 명령의 문서 수 제한은 아닙니다.
- **추가 검색 횟수** (기본 1): 자동 분석이 갱신할 기존 문서를 확실하게 찾지 못했을 때 더 찾아볼 횟수입니다. 새 후보가 발견되면 재분석할 수 있어 추가 시간과 호출이 발생할 수 있습니다.

### 5. 작업 모델과 정본 집필 문체

**작업 모델**은 위키 AI 작업에 **보조 모델 / 메인 모델** 중 무엇을 사용할지 정합니다. 보조 모델을 쓰면 대화용 모델과 위키 정리용 모델을 분리할 수 있습니다. 메인 모델을 골라도 위키 작성은 대화 응답과 별도의 호출입니다.

**정본 집필 문체** (**정본 문체**)는 사건 요약과 정본의 표현 밀도를 정합니다. 기본은 **간결**이며 표준·초압축·사용자 지정도 선택할 수 있습니다. 작성 언어와는 별개이고, 사용자 지정 문체는 최대 1,000자입니다.

능력치·소지품·관계처럼 **무엇을 계속 추적할지**는 **위키 프롬프트 프리셋**과 캐릭터·현재 챗의 **Wiki Guide**로 지정합니다. 문체 설정은 표현 방식이고 Wiki Guide는 기록할 요소에 대한 지침입니다. 자동 작성에서는 채팅에 없는 사실을 확정 정보로 만들어 넣는 권한이 되지는 않습니다.

## 자동 분석과 추가 분석

- 답변은 다음 사용자 메시지에 대한 새 답변 생성이 성공하거나, 사용자가 **현재 메시지로 확정**할 때 분석 대상이 됩니다. 재생성·스와이프 후보는 확정 전까지 기록하지 않습니다.
- 자동 분석은 확정된 내용에서 사건과 지속적으로 기억할 정보를 찾아 위키에 반영합니다.
- **추가 분석**은 최신 응답 가운데 아직 적용되지 않은 정보를 다시 검사합니다. 이미 적용된 정본은 제외하므로 누락 점검에 사용할 수 있습니다.
- 분석이 실패해도 채팅 원문은 사라지지 않습니다. 상단의 상태 메시지와 **로그**에서 원인을 확인할 수 있습니다.

## 화면 구성

- **작업 공간**: 문서 목록, Markdown 편집기, 위키 관리자 명령을 함께 표시합니다.
- **이야기**: 활성 사건을 시간 순서로 살펴보고 연결된 채팅 근거로 이동합니다. 사건의 제목이나 이야기 요약을 편집하면 여기도 같은 내용으로 갱신됩니다.
- **찾기**: 현재 위키와 채팅의 문자열을 찾아 바꿉니다. 실행 전 결과 범위를 확인하세요.
- **로그**: AI 요청과 실제 정본 처리 결과를 한 최신순 흐름에서 확인합니다. 정상 생성은 재시도로 표시하지 않으며, 각 요청의 안정적인 로그 ID를 Markdown 보고서에서도 그대로 사용합니다. 사건 근거는 새 기록부터 제목과 ID를 함께 표시하고, 여러 조각의 추가 지침·채팅 기록은 합친 토큰과 범위로 보여 줍니다. 프롬프트 본문이나 API 키는 표시하지 않습니다.
- **설정**: 현재 챗의 작업 모델, 최근 메시지 수, 위키 작성 언어·문체와 토큰 예산을 조절합니다.

## 문서 편집과 안전장치

왼쪽 파일 트리에서 문서를 고르고 **타입**과 **이름**을 수정한 뒤 본문을 편집합니다.

- **저장**: 현재 제목, 유형과 Markdown 본문을 저장합니다. 기존 문서를 덮어쓰기 전 버전은 history에 보존됩니다. 사건은 제목과 본문을 수정할 수 있지만 사건 유형과 연결된 채팅 출처는 유지됩니다.
- **되돌리기**: 저장하지 않은 현재 편집 내용을 마지막으로 불러온 상태로 되돌립니다.
- **로어북에 복사**: 저장된 문서를 캐릭터 로어북의 비활성 항목으로 복사합니다. 저장하지 않은 변경이 있으면 먼저 저장해야 합니다.
- **삭제**: 일반 문서는 휴지통으로 이동합니다. 사건 문서는 편집할 수 있지만 삭제할 때는 명시적인 확인 뒤 영구 삭제됩니다.

문서 이름이나 유형을 바꿔도 내부 ID는 유지됩니다. 직접 연결된 위키 링크는 안전하게 갱신되며, 동시에 다른 편집이 발생해 내용 hash가 달라지면 저장을 중단해 덮어쓰기를 방지합니다.

## 문서 유형

- **캐릭터**: 정체성·역할, 성격, 능력·규칙, 관계, 지식, 목표, 소지품·제약과 열린 연속성. `현재 상태`는 유용할 때 권장하며 필수 형식이 아닙니다. 작중 행적은 세부 일지가 아니라 사건 링크가 붙은 큰 전환점 약 3~6개만 둡니다.
- **장소**: 공간의 성격, 위치, 변화와 관련 인물
- **세력**: 집단의 목적, 구성원, 관계와 영향력
- **사물**: 중요한 물건, 소유자, 상태와 기능
- **개념**: 규칙, 현상, 설정과 추상적인 세계관 정보
- **현재 장면**: 지금 진행 중인 시점·장소·참여자와 직전 상태
- **기타**: 위 유형에 맞지 않는 지속 정보
- **사건**: 확정된 변화의 기록. 자동으로 만들며, 사용자가 제목과 본문을 직접 고칠 수 있습니다. 수정된 이야기 요약은 **지금까지의 이야기**에도 반영됩니다.

기존 정본을 자동 갱신할 때 AI는 문서 전체를 다시 작성하지 않습니다. 변경된 H3 절의 본문만 생성하고, 프로그램이 현재 문서의 내용 hash를 확인한 뒤 해당 절에만 적용합니다. 응답에서 생략된 제목과 절은 기존 내용을 그대로 유지합니다. 새 정본은 기존 절이 없으므로 필요한 초기 절을 모두 생성합니다.

## 컨텍스트 정책

일반 문서를 우클릭하면 다음 응답에 포함되는 방식을 바꿀 수 있습니다.

- **항상 컨텍스트에 포함**: 관련도와 관계없이 필수 문서로 사용합니다.
- **관련 있을 때 포함**: 현재 입력과 제목·본문·위키 링크가 관련될 때만 후보가 됩니다. 기본값입니다.
- **자동 컨텍스트에서 제외**: 자동 조회에서는 제외하지만 사용자가 직접 선택해 참고할 수 있습니다.

필수 문서가 고정된 문서 수나 토큰 한도를 넘으면 일부를 몰래 버리지 않고 오류로 알립니다.

## 파일 트리와 건강도

- **문서**는 현재 정본 문서 수입니다.
- **끊어진 링크**는 대상 문서를 찾지 못한 `[[위키 링크]]` 수입니다.
- **연결 없음**은 다른 현재 문서와 연결되지 않은 정본 수입니다.

이 진단은 현재 파일에서 계산한 안내 정보이며 원문을 자동으로 고치지 않습니다. 파일을 외부 편집기에서 수정했다면 메모리 위키를 다시 열어 최신 상태를 불러오세요.

## 위키 관리자 명령

하단 명령 입력창은 자연어로 여러 문서를 한 번에 만들거나 수정하는 직접 편집 도구입니다. 예를 들어 “등장인물별 문서를 만들고 현재 관계를 반영해”처럼 원하는 결과를 구체적으로 적을 수 있습니다.

- 사용자 명령이 편집 내용의 최우선 지시입니다.
- 기존 사건의 제목과 본문도 수정할 수 있습니다. 사건 ID·유형·파일 경로와 연결된 채팅 출처는 유지됩니다.
- AI는 제목과 본문 초안을 만들지만 실제 파일 경로, ID와 frontmatter는 프로그램이 검증하고 결정합니다.
- 변경 전 내용은 history 또는 trash에 보존되고, 현재 hash가 예상과 다르면 충돌한 문서만 중단합니다.
- `Ctrl+Enter`로 실행할 수 있습니다. 실행 결과와 실패 항목은 명령 패널과 로그에서 확인합니다.

## 문제가 생겼을 때

1. 상단 상태 메시지와 **로그**에서 실패 이유를 확인합니다.
2. 저장 버튼이 비활성이라면 제목과 본문이 비어 있지 않은지, 위키 리부트처럼 편집을 잠그는 작업이 진행 중인지 확인합니다.
3. 로어북 복사가 비활성이라면 현재 문서를 먼저 저장합니다.
4. 외부 편집 내용이 보이지 않으면 메모리 위키를 닫았다가 다시 엽니다.
5. 충돌 경고가 나타나면 현재 파일을 다시 불러온 뒤 변경 내용을 비교하여 적용합니다.

Markdown 파일이 서사 메모리의 정본입니다. 생성 캐시나 화면 진단은 언제든 다시 만들 수 있으며 정본을 대신하지 않습니다.
