# 남은 V1·V2 파일에서 목록 복구하기

캐릭터·페르소나 등의 파일은 남아 있는데 목록이 비었거나 인덱스 두 개가 모두 사라진 경우, 오프라인 복구 도구로 별도 세이브 복사본을 만들 수 있습니다. 다음 두 형식을 지원합니다.

- **V1:** `characters/<ID>/metadata.json`, 대화의 `metadata.json`·`messages.jsonl`, `personas/<ID>.json` 같은 항목 파일과 `settings/app.json`, `secrets/credentials.json`, `kv/manifest.json` 및 연결된 `kv/objects` 파일이 남아 있는 저장소입니다. KV 연결표는 정상적인 `.bak`이 있으면 대신 사용합니다.
- **V2:** 이름별 폴더에 `character.json`, `persona.json`과 각 `manifest.json`이 있는 저장소입니다.

V1은 실제 항목 파일에서 목록을 재구성한 후 **복사본만 V2로 변환**합니다. 기존 `database.bin` 캐시는 복구 자료로 사용하지 않으므로, 빈 캐시가 남아 있어도 실제 파일에 있는 항목을 찾습니다. 구형 hex 파일이나 SQLite만 남은 저장소, V1·V2 파일이 섞인 저장소는 지원하지 않습니다.

## Windows: 더블클릭으로 복구

1. **v0.9.27 이상 Windows 포터블 ZIP을 새 폴더에 압축 해제**하고 기존 리스바드 서버 창을 닫으세요. 남은 세이브는 옮기거나 덮어쓰지 마세요.
2. 압축을 푼 폴더에서 **`recover-save.bat`을 더블클릭**하세요. 별도로 Node.js를 설치하거나 명령어를 입력할 필요가 없습니다.
3. 첫 창에서 **남아 있는 원본 세이브 폴더**를 선택하세요. `characters`, `personas`, `settings` 등이 들어 있는 폴더입니다.
4. 다음 창에서 **복구 결과를 보관할 폴더**를 선택하세요. 원본 세이브 바깥의 여유 공간이 있는 위치를 고르면 그 안에 고유한 결과 폴더가 자동 생성됩니다.
5. 완료 안내 뒤 열린 결과 폴더에서 **`Start-Recovered-RisuBard.bat`을 더블클릭**하세요. 복구된 세이브로 리스바드가 실행됩니다.

이후에도 복구본을 사용하려면 같은 `Start-Recovered-RisuBard.bat`으로 실행하세요. 원래 `RisuBard.exe`는 원래 데이터 경로를 사용합니다. 프로그램 폴더와 복구 결과 폴더를 이동하면 복구본 실행기의 경로가 끊길 수 있으므로 그대로 보관하세요. 기존 서버가 같은 포트를 사용 중이면 실행기가 종료를 안내하며 임의로 서버를 강제 종료하지 않습니다.

실패하면 결과 폴더의 `RECOVERY-ERROR.txt`와 `report.json`에 이유가 남습니다. 원본을 지우거나 빈 세이브로 덮어쓰지 말고 이 오류를 확인하세요. 두 폴더 선택 창에서 취소하면 복구를 시작하지 않습니다.

## 명령어로 실행

서버를 종료하고 다음 명령의 두 경로를 실제 경로로 바꿔 실행하세요. 출력 폴더는 아직 존재하지 않아야 하며, 그 상위 폴더는 존재해야 합니다. 원본과 출력은 서로 포함되지 않는 별도 위치여야 합니다. 원본 전체 복사용 공간이 필요하며, V1은 복사본 안에 이전 파일을 보존하면서 새 형식과 임시 파일을 생성하므로 추가 공간이 필요합니다.

```powershell
node "C:\RisuBard\scripts\recover-save-index.cjs" "D:\남은세이브" "D:\인덱스복구결과"
```

스크립트 경로도 설치 위치에 맞춰 바꿀 수 있습니다. 원본은 읽기만 하며, 서버를 실행하거나 활성 세이브 경로를 바꾸지 않습니다. 원본 안의 기존 인덱스를 먼저 지울 필요도 없습니다.

## 결과 확인

- `report.json`: 복구 상태, 확인한 항목 수, 문제 파일과 경고입니다. 원본 파일·폴더가 실행 전후 같은지도 확인합니다.
- `rebuilt-index.json`: 실제 항목 파일에서 재구성한 목록 후보입니다. 누락·충돌이 있으면 불완전한 후보이므로 바로 적용하지 마세요. 초기에 중단되면 생성되지 않을 수 있습니다.
- `recovered/`: 모든 검증을 통과한 경우에만 만드는 세이브 복사본입니다. 이 안의 `index/sidebar.json`과 `settings/entity-order.json`이 복구되어 있습니다.
- `candidate/`: 복구가 중단된 경우 남는 검토용 복사본입니다. 완성된 세이브로 사용하지 마세요.
- `rebuilt-v1-index.json`, `original-indexes/`: V1에서 재구성한 목록과 남아 있던 기존 인덱스 기록입니다. V1 변환 후 실제 내용이 같은지도 대조하며, 이전 항목 파일은 복구본의 `trash/layout-<ID>/`에도 보존합니다.

`report.json`의 `status`가 `recovered`이고 `sourceUnchanged`가 `true`일 때만 `recovered/`를 복구된 데이터 루트로 사용하세요. 처음 열었을 때 캐릭터·대화·이미지와 프롬프트·페르소나 선택을 확인하고, 확인을 마칠 때까지 원본을 보존하세요. 보고서와 복사본에는 개인 데이터가 있으므로 공개 게시하지 마세요.

## 복구 범위와 제한

캐릭터·대화·페르소나·모듈·프롬프트·전역 로어북의 활성 폴더를 읽어 원래 ID와 실제 경로를 다시 연결합니다. 같은 이름의 폴더도 ID로 구분하며, 기존 빈 인덱스에 없는 항목도 찾습니다. 휴지통·백업의 항목은 활성 목록에 자동 추가하지 않습니다.

남아 있는 인덱스와 `.bak`의 순서 기록은 참고만 합니다. 기록에서 누락된 항목도 포함하고, 순서를 알 수 없는 항목은 폴더명 순서로 추가합니다. 원래 표시 순서와 숫자 인덱스에 연결된 선택 상태는 완전히 복구되지 않을 수 있으므로 프롬프트·페르소나·대화 선택을 확인해야 합니다.

중복 ID, 누락된 manifest·본문, 손상된 대화 JSONL, 필수 설정 유실, 이미지 연결 오류와 미완료 저장 journal은 보고서에 남기고 완성본 게시를 중단합니다. V1의 `kv/manifest.json`과 그 백업이 모두 없거나, V2의 `settings/asset-files.json`까지 유실된 경우 이미지 연결을 추측해 만들지 않습니다. 삭제된 본문 자체를 재생성하는 도구는 아닙니다.
