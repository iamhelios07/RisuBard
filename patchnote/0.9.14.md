# RisuBard v0.9.14

이번 버전은 채팅별 토글 프리셋 고정을 다시 확장하고, 생성 파라미터의 표시·전송 안정성, 로어북·Grimoire 사용성, BardWiki의 퍼스트 메시지 반영과 캐릭터 카드 호환성을 함께 개선했습니다.

## [기능] 채팅별 토글 프리셋 고정

- **프리셋 이름 표시:** 토글 프리셋을 적용하면 `채팅별 프리셋 고정` 버튼에 적용한 프리셋 이름을 표시합니다. 프리셋을 따로 선택하지 않고 고정하면 현재 값이 `직접 설정` 기준선으로 저장됩니다.
- **변경 상태 추적:** 고정한 기준값과 달라진 토글 수를 버튼에 표시하고, 버튼에 마우스를 올리면 변경된 토글의 이름과 현재 표시값을 줄별로 확인할 수 있습니다.
- **변경 항목 강조:** 기준값과 달라진 토글 행의 글자와 고정 버튼을 빨간색으로 표시해 수정된 항목을 바로 찾을 수 있습니다.
- **한 번에 되돌리기:** 고정 버튼 오른쪽에 초기화 버튼을 추가했습니다. 누르면 마지막으로 고정한 프리셋 또는 직접 설정 기준값으로 정확히 돌아가며, 이후 추가된 임시 토글 값도 함께 정리합니다.
- **기존 채팅 호환:** 이전 버전에서 이미 채팅별 토글을 사용하던 채팅은 현재 고정값을 자동으로 `직접 설정` 기준선으로 마이그레이션합니다.

## [안정성] 모델·프롬프트 파라미터

- **온도 입력 단위 정상화:** 레거시 모델 설정에서도 프롬프트 프리셋과 같은 실제 단위로 온도를 표시하고 편집합니다. `1`을 입력했는데 요청에는 `0.01`로 적용되던 문제를 수정했습니다.
- **비활성값 표시 정상화:** 비활성 온도와 샘플링 파라미터가 내부값 `-1000`으로 노출되지 않고 스위치 꺼짐으로 표시됩니다.
- **생성 파라미터 안전 검증:** 모델·프롬프트 프리셋과 일반·분리 파라미터에서 허용 범위를 벗어난 온도·Top K 등의 값을 프로바이더 요청에서 제외하며, 직접 요청 경로에도 같은 기준을 적용했습니다. `0.01`처럼 범위 안의 값과 사용자가 저장한 원본 값은 그대로 보존합니다.

## [UI] 캐릭터 사이드바와 프리셋 메뉴

- **바인딩 순서 정리:** 캐릭터 사이드바에서 `페르소나 바인딩`을 `프롬프트 바인딩` 위로 이동했습니다.
- **명칭 명확화:** 기존 `채팅별 토글`을 `채팅별 프리셋 고정`으로 바꿔 이 기능이 시스템 프롬프트의 토글 옵션 묶음을 채팅별로 고정한다는 점을 명확히 했습니다.
- **프리셋 메뉴 가림 수정:** 토글 프리셋의 오른쪽 옵션 메뉴가 모달의 블러 배경 아래에 표시되어 조작할 수 없던 문제를 수정했습니다. 공용 드롭다운 레이어 규칙과 회귀 검사도 함께 보강했습니다.

## [UI] 로어북 폴더 표시 순서

- **폴더 자식 위치 수정:** 폴더를 열면 포함 항목이 목록 상단으로 튀어 올라가지 않고 해당 폴더 바로 아래에 표시됩니다. 저장된 로어북 순서는 변경하지 않습니다.

## [Grimoire] 검색 옵션 안내 개선

- **`키+관련도`로 명칭 변경:** 기존 `관련도 검색`이 실제로는 키·별칭 직접 적중을 우선하고 관련도 검색도 함께 사용한다는 점을 명확히 표시합니다.
- **옵션별 도움말:** 활성화 드롭다운의 각 옵션에 마우스를 올리거나 키보드로 선택하면 왼쪽 툴팁에서 동작을 바로 확인할 수 있습니다. 단일 항목과 일괄 편집에 모두 적용됩니다.

## [BardWiki] 퍼스트 메시지 분석 반영

- **퍼스트 메시지를 분석 근거에 포함:** 선택된 퍼스트 메시지를 스크립트 처리한 뒤 자동·수동 확정, 추가 분석, 위키 리부트와 BARDCHAT의 `챗` 맥락에 반영합니다.
- **최근 메시지 경계 적용:** `분석 최근 메시지`가 5개라면 퍼스트 메시지는 이후 저장 메시지 5개까지 함께 반영되고, 6번째부터 제외됩니다. 퍼스트 메시지 제외 옵션을 켠 챗에는 주입하지 않습니다.

## [호환성] 캐릭터 엑스포트

- **Grimoire 데이터 포함:** PNG·JSON·CHARX 캐릭터 엑스포트에서 Grimoire 상태를 `data.extensions.risubard.bardLore`에 함께 보존합니다.
- **표준 로어북 호환성 유지:** 표준 `character_book`은 기존 형식을 유지하므로 다른 앱은 알 수 없는 RisuBard 확장을 무시하고 일반 로어북을 계속 읽을 수 있습니다. 손상된 Grimoire 확장도 표준 로어북 임포트를 막지 않습니다.
