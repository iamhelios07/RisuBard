# RisuBard v0.9.17

v0.9.17은 v0.9.16의 모든 변경을 포함하면서, 창과 플러그인 화면의 드로우 오더를 안정적이던 이전 방식으로 복구한 긴급 패치입니다. 아래에 이번 복구 내용을 먼저 배치하고 v0.9.16의 전체 변경 내역을 그대로 이어서 제공합니다.

## [UI] 창 드로우 오더 이전 방식 복구

- **정적 계층으로 복귀:** 0.8.10 이후 적용된 전역 고정 계층과 0.9.15의 동적 드로우 오더 관찰을 제거하고, 각 창·메뉴·툴팁·전체 화면 플러그인이 원래 사용하던 개별 정적 `z-index` 방식으로 되돌렸습니다. 플러그인 전체 화면이 다른 창 뒤에 가려져 최소화나 닫기 조작이 막히던 문제를 해결합니다.
- **플러그인 버튼 배치 복구:** 플러그인 액션 버튼을 채팅 패널 안에 제한하던 변경을 철회하고, 기존처럼 화면을 기준으로 배치하고 이동하도록 복구했습니다.

---

아래는 v0.9.16의 전체 변경 내역입니다. 드로우 오더와 플러그인 버튼 위치에 관한 이전 설명은 위 복구 내용으로 대체됩니다.

## [안정성] 모듈 가져오기와 페르소나 빌더 핫픽스

- **대용량 모듈 멈춤 수정:** 압축 항목이 많은 CHARX와 모듈을 가져올 때 `Reading` 단계에서 멈출 수 있던 문제를 수정했습니다.
- **페르소나 빌더 표시 수정:** 페르소나 관리 화면에서 `페르소나 빌드`를 열었을 때 빌더가 기존 창 뒤에 가려져 사용할 수 없던 문제를 수정했습니다.
- **BardWiki 리부트 400 오류 수정:** 의미 분석 뒤 정본 갱신 단계에서 일부 provider가 네이티브 JSON Schema 요청을 거부해 `HTTP 400`으로 리부트가 중단되던 문제를 수정했습니다. 같은 Schema를 프롬프트로 전달하는 방식으로 정확히 한 번만 재시도하며, 강등 응답도 올바르지 않으면 반복 요청하지 않고 안전하게 실패합니다.

## [성능] 모듈·캐릭터 가져오기

- **자산 일괄 저장 확대:** 모듈과 캐릭터의 여러 자산을 더 큰 묶음으로 저장하고 파일 쓰기를 병렬 준비해, 메모리 안전 한도를 유지하면서 가져오기 대기 시간을 줄였습니다.

## [기능] BardWiki 동적 캐릭터 정본과 과거 사건 회수

- **캐릭터 문서를 다이나믹 로어북으로 사용:** 정체성, 성격, 능력, 관계, 지식, 목표, 소지품과 미해결 상태처럼 다음 장면에 필요한 지속 정보를 캐릭터 문서에 갱신합니다. `현재 상태` 절은 권장 형식으로 유지하되, 절이 없다는 이유만으로 저장을 거부하거나 불필요한 구조 보완을 실행하지 않습니다.
- **전환점에서 상세 사건으로 이동:** 캐릭터의 `작중 행적`은 필요할 때만 주요 전환점 3~6개를 담는 간결한 지도로 사용하고, 세부 행동과 연대기는 사건 문서와 원문 근거에서 가져옵니다.
- **사건 전용 조회 예산:** 과거·원인·세부·연대기 질문에는 `사건 상세 조회 토큰`을 별도로 배정해 관련 사건을 더 충실히 회수합니다. 현재 상태 질문에는 이 예산을 쓰지 않으며, 전체 조회는 `위키 조회 토큰 절대 상한`을 넘지 않습니다.
- **사건 출처 원문 직접 회수:** 관련 사건이 선택되면 연결된 과거 채팅 원문을 안정 ID로 직접 찾아 우선 반영합니다. 현재 입력과 표현이 달라도 정확한 근거를 가져오며, 선택되지 않은 사건의 비슷한 표현이 끼어드는 문제를 줄였습니다.
- **원문 수와 토큰 설정:** `과거 원문 최대 수`를 기본 8개, 최대 32개 범위에서 정할 수 있으며 기존의 최종 2개 제한을 제거했습니다. `자료별 검색 토큰 상한`과 전체 조회 예산이 허용하는 만큼 출처 원문을 채우고, 남는 범위만 어휘 검색 결과로 보충합니다.
- **정본 수정 실패 복구:** 단일 정본 문서의 구조화 응답이 올바르지 않으면 안전한 `###` 절 단위 Markdown 수정으로 한 번 더 시도해, 유효한 변경을 문서 전체 실패로 잃지 않도록 했습니다.

## [기능] BardWiki 활동 기록과 근거 표시

- **하나의 시간순 기록:** AI 요청과 `정본 처리` 결과를 별도 구역으로 나누지 않고 실제 시간순으로 함께 표시합니다. 일반 요청을 재시도로 추정해 잘못 붙이던 `응답 시도` 표시는 제거했습니다.
- **안정적인 요청 번호:** 화면 상세에서는 `로그 ID #ID`, Markdown 내보내기에서는 `요청 #ID`로 저장된 번호를 사용해 같은 요청을 일관되게 추적할 수 있습니다.
- **주입 내역 정리:** 여러 추가 지침과 이어진 채팅 기록 구간을 각각 하나의 항목으로 묶어 토큰 합계와 범위를 읽기 쉽게 표시합니다. `5~5` 같은 단일 범위는 `5`로 줄여 표시하고, 묶기 전 세부 출처는 접어서 확인할 수 있으며 저장된 원본 근거와 실제 모델 입력은 변경하지 않습니다.
- **검색 근거 이름 개선:** 사용된 사건은 ID 경로 대신 정본 제목으로 표시하고, 과거 원문은 `턴 N 입력/응답`과 `출처 기반` 또는 `어휘 검색`으로 구분해 어떤 기억이 답변에 쓰였는지 바로 확인할 수 있습니다.

## [기능] BARDCHAT 공간 효율적인 도구 모음과 한 단계 복원

- **한 줄 도구 모음:** `BARDCHAT`, `컨텍스트`, 복원, `명령어 리스트`, `지시 실행`을 같은 행에 배치해 편집 공간을 넓혔습니다. `지시 실행`은 행의 가장 오른쪽에 고정됩니다.
- **컨텍스트 플라이아웃:** `컨텍스트`를 누르면 주입 대상을 한 열 메뉴로 펼쳐 선택할 수 있으며, 메뉴 바깥을 클릭하면 자동으로 닫힙니다.
- **현재 문서 자동 입력:** 명령어 템플릿을 넣을 때 현재 BardWiki에서 선택한 문서 이름을 `대상:`의 `<문서 제목 또는 ID>` 자리에 자동으로 채웁니다.
- **마지막 작업 복원:** 복원 아이콘으로 마지막 BARDCHAT 실행 직전의 위키 스냅샷 하나를 되돌릴 수 있습니다. BARDCHAT 창을 닫거나 다른 캐릭터를 봐도 유지되며, 이후 직접 수정이 감지되면 안전을 위해 복원을 거부합니다. 성공적으로 복원하거나 앱·서버를 다시 시작하거나 다음 실제 BARDCHAT 변경이 확정되면 기존 스냅샷은 제거·교체됩니다.
- **이번 실행의 `New` 표시:** BARDCHAT이 수정한 문서에 `New`를 표시하고, 이전 표시는 이번 실행에서 실제로 바뀐 문서 목록으로 교체합니다. 복원하면 해당 표시도 함께 지웁니다.

## [기능] Grimoire AI 분석 작업대

- **크기를 조절하는 두 영역 분석 화면:** 왼쪽에는 분석 설정·예상 요청량·실행 제어를, 오른쪽에는 폴더 구조를 유지한 대상 목록을 배치했습니다. 창 가장자리와 두 영역 사이의 핸들로 크기를 조절할 수 있으며, 요청 계획 카드는 좁아진 영역에 맞춰 줄을 바꾸고 좁은 화면에서는 한 열로 전환됩니다.
- **분석 대상 직접 선택:** 타입 필터, `모두 선택`, `모두 해제`, 행 클릭과 드래그 선택으로 실제 분석할 항목만 고를 수 있습니다. 요청 계획도 선택된 대상만으로 계산됩니다.
- **진행 상태 확인:** 각 항목의 제외·대기·분석 중·완료·실패 상태를 이름 색상과 텍스트로 함께 표시합니다.
- **재사용 가능한 추천 기본값:** 새 캐릭터는 배치당 20개, 입력 12,000토큰, 출력 4,000토큰, 연결 깊이 1, 분석 온도 0.2의 안정적인 시작값을 사용합니다. 현재 다섯 가지 값을 `기본값으로 저장`하면 이후 다른 캐릭터에도 적용되며 기존 캐릭터 설정은 바꾸지 않습니다.
- **대상별 추천 설정과 안내:** `추천 설정`이 선택 항목 수와 예상 입력량을 바탕으로 배치 크기와 토큰 한도를 계산합니다. `AI 분석 설정`의 각 항목은 도움말 버튼과 마우스 툴팁으로 역할과 추천 범위를 설명하며, 요청 계획 아래의 중복 안내 문구는 제거했습니다.

## [기능] Grimoire 일반 로어북과 실시간 동기화

- **하나의 원문 유지:** 일반 로어 항목의 이름·키·본문 같은 원본 필드는 캐릭터 로어북을 단일 기준으로 사용하고, Grimoire에는 검색 메타데이터와 AI 파생 항목만 별도로 보존합니다.
- **양방향 편집 반영:** 일반 로어북에서 바꾼 내용은 Grimoire에 즉시 반영되고, Grimoire 편집기의 일반 항목 수정도 원본 로어북에 저장됩니다. AI가 만든 파생 항목은 원본과 섞이지 않도록 독립적으로 유지합니다.
- **기존 데이터 자동 이전:** 복제된 항목을 저장하던 이전 Grimoire 형식은 불러올 때 새 공유 원본 구조로 정규화하며, 캐릭터 카드 가져오기·내보내기에서도 현재 로어북과 결합된 내용을 유지합니다.

## [문서] Grimoire 로어북 작성 안내

- **AI 분석 종합 도움말:** AI 분석 창 제목 옆의 `도움말`에서 Grimoire의 목적과 사용 사례, 수동으로 입력해야 하는 키·활성화 규칙, 별칭·태그·요약·facet·명시 링크, 검색 예산, 분석 초안 승인 과정을 쉬운 말로 안내합니다.
- **도움말 목차 탐색:** Grimoire 편집기 도움말에 섹션 목차를 추가해 활성화 규칙, 검색 설정과 작성 지침으로 바로 이동할 수 있습니다. 넓은 화면에서는 왼쪽 고정 목차로, 좁은 화면에서는 상단 목차로 표시됩니다.
- **비밀과 복선 작성법:** 공개 인격과 비밀 인격을 하나의 정체성으로 유지하는 법, 지식 경계·복선·공개 조건을 작성하는 법, 기본 키와 보조 키가 AND 잠금이 아니라 대안 관계로 작동한다는 주의를 브루스 웨인·배트맨 예시와 항목 체크리스트로 안내합니다.

## [UI] 모달·메뉴 계층과 플러그인 버튼 위치

- **공통 오버레이 계층:** 모달, 경고, 드롭다운, 선택 메뉴, 툴팁, 알림과 전체 화면 보기를 하나의 제한된 계층 규칙으로 정리했습니다. 여러 창을 겹쳐 열 때 메뉴가 배경 아래로 숨거나 극단적인 `z-index`끼리 충돌하던 문제를 줄였습니다.
- **플러그인 버튼을 채팅 영역에 제한:** 화면 우측 하단의 컵케이크 같은 플러그인 액션 버튼은 BardWiki 위가 아니라 채팅 패널 안에서만 배치·이동됩니다.
- **플러그인 버튼 조작:** 버튼은 마우스로 끌거나 키보드 화살표로 옮길 수 있고 `Home`으로 기본 위치에 되돌릴 수 있습니다. 버튼의 플러그인 이름은 툴팁으로 확인하며, 필요하면 `설정 → 플러그인`의 전원 버튼으로 해당 플러그인을 끌 수 있습니다.

## [호환성] 로컬 모델 요청과 기본 실행 포트

- **Ollama 구조화 응답 지원:** 내부 비스트리밍 요청에서 JSON Schema, 최대 출력 토큰과 온도를 Ollama에 전달합니다. 일반 채팅의 스트리밍은 유지하고, 요청 취소도 Ollama 호출까지 전달합니다.
- **생성 파라미터 검증 통일:** 비활성값과 허용 범위를 벗어난 온도·Top K·Top P·패널티 값을 레거시 및 공통 프로바이더 요청에서 제외해 잘못된 값이 전송되지 않도록 했습니다.
- **기본 포트를 `7777`로 변경:** Windows 포터블, Linux·macOS·Termux, Docker와 개발 프록시의 기본 접속 주소를 `http://localhost:7777`로 통일했습니다. 기존처럼 `PORT` 환경 변수를 지정하면 다른 포트를 사용할 수 있습니다.
