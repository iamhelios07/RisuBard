# RisuBard v0.9.27

업데이트 후 이관 화면이 열리지 않거나 재시작 실패로 표시되던 문제를 수정하고, Docker 이관과 원본 보존을 보강했습니다. 파일만 남은 V1·V2 세이브를 복구하는 Windows BAT 실행기와 자동저장 안정성 개선도 포함합니다.

## [안정성] 업데이트 후 저장소 이관 안내

- **업데이트 완료 판정:** 새 버전이 저장소 이관 동의를 기다리는 동안 구버전 업데이트 화면에서 재시작 실패로 표시되던 문제를 수정했습니다. 사전 검사가 오래 걸려도 안내 화면을 열 수 있으며, HTTPS 연결도 유지합니다.
- **이관 오류 안내:** 이관 사전 검사에서 참조 이미지 누락 등의 문제가 발견되면 서버가 바로 종료되는 대신 원인과 백업 안내를 표시합니다. 오류가 있는 저장소를 자동으로 덮어쓰지 않으며, 별도 폴더 백업을 만들 수 있습니다.
- **최신 저장 내용 이관:** 구형 호환 캐시보다 V1 파일 정본을 우선해 최근 대화와 설정이 이전 상태로 되돌아가지 않도록 수정했습니다. 동시 실행과 강제 종료가 겹쳐도 진행 중인 이관의 복구 기록을 다른 실행이 지우지 않도록 보강했습니다.
- **대용량 이관 응답 개선:** 이미지가 많은 세이브를 검사할 때 불필요한 메모리 할당을 줄였습니다. 이관 시작 시 중복 사전 검사로 응답이 늦어지던 문제를 수정했으며, 실제 이관 작업의 데이터·용량 검사는 유지합니다.
- **빈 V1 목록의 이관 차단:** 캐릭터·대화·페르소나 등의 실제 파일이 남아 있는데 목록만 비어 있으면 자동 이관을 중단하고 복구 도구를 안내합니다. 빈 목록을 정상 세이브로 이관해 데이터가 사라진 것처럼 보이던 경우를 방지합니다.

## [안정성] 남은 세이브 파일에서 목록 복구

- **더블클릭으로 목록 복구:** Windows 포터블의 `recover-save.bat`을 실행하고 원본 세이브와 결과 보관 폴더를 선택하면, 남은 V1·V2 파일에서 목록을 재구성합니다. 원본은 그대로 보존하며 결과 폴더의 `Start-Recovered-RisuBard.bat`으로 복구본을 바로 열 수 있습니다.
- **이관 전 V1 세이브 복구:** 인덱스가 모두 사라지고 빈 세이브 캐시가 남아 있어도, 캐릭터·대화·페르소나 등의 실제 파일과 KV 이미지 연결표를 기준으로 복구를 시도합니다. 복사본에서 목록을 만든 뒤 V2로 변환하고 내용을 대조하며, 이미지·초안·위키도 보존합니다.
- **누락·충돌 안내:** 중복 ID·본문 누락·이미지 연결 오류는 보고서에 표시하고 복구 완료로 처리하지 않습니다. 기존 순서 기록이 없으면 복구 후 프롬프트·페르소나·대화 선택을 확인해야 합니다.

## [안정성] 자동저장 중 수정 내용 보존

- **자동저장 중 편집 유지:** 페르소나 이름과 설명을 수정하고 창을 닫은 뒤, 일부 수정이 사라지고 이전 내용이 응답에 사용되던 문제를 수정했습니다. 로어북·모듈·프롬프트·채팅에도 같은 보호를 적용하고, 이미지 변경을 저장할 때도 후속 편집이 유지되도록 보강했습니다.

## [안정성] 위키 저장 실패 재시도

- **위키 저장 실패 재시도:** 정본 문서 일부를 저장하지 못한 턴이 확정 완료로 처리되지 않도록 수정했습니다. 저장된 사건과 성공한 문서의 영수증은 유지하고 실패한 턴을 재시도 대상으로 남깁니다.

## [호환성] Docker 저장소 이관

- **컨테이너 이관 화면:** 서버 로그에 표시되는 전용 링크로 이관 화면을 열 수 있습니다. 해당 링크의 임시 접근 키 없이 다른 접속자가 이관이나 백업을 실행할 수 없도록 보호합니다.
- **볼륨과 원본 보존:** Docker 볼륨 안에서 이관하고 이전 세이브 전체를 같은 볼륨에 보존합니다. 작업 중단 뒤에는 원본을 복구하며, 컨테이너 재시작 후 남은 잠금 때문에 재시도가 막히는 문제도 보완했습니다.
- **동시 컨테이너 보호:** 같은 세이브 볼륨을 여러 컨테이너가 동시에 이관하지 못하도록 보호하고, 이관 중 컨테이너가 강제 종료되면 다음 실행에서 잠금을 다시 확보할 수 있도록 수정했습니다.

## [호환성] 포켓리스 백업 가져오기

- **대화 복원 오류 수정:** 대화 본문과 이전 로딩 상태 표식이 함께 남아 있는 포켓리스 백업을 불완전한 채팅으로 오인해 가져오기가 중단되던 문제를 수정했습니다. 실제 본문이 누락된 백업은 계속 차단해 기존 데이터를 보호합니다.

## [성능] 요청 로그 메모리 부담 완화

- **누적 로그 메모리 절감:** 서버 시작·로그 조회·용량 정리 시 전체 로그를 메모리에 유지하지 않고 나누어 읽도록 바꿨습니다. 로그를 정리할 때도 전체 내용을 한 번에 복사하지 않습니다.
- **사용량 통계 경량화:** 사용량 로그에 요청·응답 본문을 중복 저장하지 않습니다. 기존 사용량 로그는 첫 실행 시 통계 내역을 유지하면서 정리하고, 이전 파일은 백업으로 보존합니다.
